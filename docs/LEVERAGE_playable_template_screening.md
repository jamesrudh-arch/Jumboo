# Playable-project screening for LEVERAGE

Screened 27 November 2026 for a third-person, mobile-compatible starting point that could support the requested warehouse and city without replacing Marcus, copying another game's story or using a placeholder world. This is a completed source and technical screening, **not** a finished LEVERAGE scene. Repositories were cloned outside this checkout; their assets or code were not copied into the game.

## Measured candidate: OpenCity

- [webgl-games/opencity](https://github.com/webgl-games/opencity), commit `ba9514cdd88ecc2d40ecad503a644449fc98e665`. Its code and procedurally built scene are MIT, and its credits identify the Quaternius Universal Animation Library GLB as CC0. Its README describes third-person walking, punch, vehicle entry, driving, traffic and pedestrians. No mobile touch controls or mission system are provided. It targets Godot 4.7; an iPhone/Xogot result is not established.
- Actual investigation: cloned the files and inspected the included `screenshots/walk.png`, player, vehicle and city scripts. The image shows basic block buildings and a mannequin; the README explicitly describes its environment and vehicles as placeholder geometry, with no audio. It does **not** meet the owner's visual/art-direction requirement and must not replace Marcus or serve as the finished city.
- Technical experiment: on a **temporary modified copy**, the included 7.3 MB animation GLB was parsed with `GLTFDocument`, packed as a local `.scn`, and the player scene was pointed to it. Because the Godot 4.4.1 runtime GLB importer preserved `_Loop` suffixes, the temporary player script was changed to match the actual animation names; the screenshot call was disabled because the test build has no renderer. This is an adaptation, not an unmodified Godot 4.7/Xogot launch. A custom Godot 4.4.1 headless template with Godot Physics 3D then executed the repository's `--walk` and `--drive` input paths for 300 physics frames each. Walking ended at `(26.000000, -0.004157, -38.778702)` at 30.6 km/h; driving entered the nearby vehicle and ended at `(23.000000, 0.694712, -66.204765)` at 80.9 km/h. The unmodified temporary import initially produced missing-animation errors; these went away after the explicit name adjustment. The build reported no renderer, a missing global script cache and dummy 2D physics. These results establish only the exercised headless movement/vehicle paths in the adapted copy, not visual quality, all interactions, sound, performance or iPhone compatibility.

## Godot's third-person shooter demo

- [Godot Engine TPS demo](https://github.com/godotengine/tps-demo), specifically Godot 4.4 commit `bd9b9ef2fdc8993515c2917d26e5cf175c4a54ce`, not the current 4.7 release. The official README describes a full demo with keyboard/gamepad movement, aiming and shooting. Code is MIT; its `LICENSE.md` states the art is CC BY 3.0 by Juan Linietsky and Fernando Miguel Calabró and music CC BY 3.0 by Christian Fernando Perucchi. It notes source Substance materials from GameTextures.com; retain and assess the full attribution and derivative-material notices before any use. No template files were incorporated.
- Actual inspection: cloned source (1.3 GB including Git history), viewed the current official screenshot and inspected the pinned 4.4 project and licence. The setting is a sci-fi facility with robots, not the specified crime-thriller city or Marcus. The pinned player GLB (`16b783ec2e19245d034326d401796b9bd2635de75f4e38917854316abeee4f9c`) parsed successfully in Godot 4.4.1 headless with five mesh nodes and 56 animation clips. This checks file parsing only; the complete TPS level was **not launched or played**, and no mobile controls, visuals, performance or Xogot compatibility were verified. Heavy 4K textures and the Forward+ presentation make mobile profiling essential. It is a possible mechanics reference, not a ready-to-use warehouse.

## Other reviewed sources and decisions

- [CityLifeOnline](https://github.com/githubxiansaiful/city-life-online-game) commit `5685f3218d7c15a3e2dc49c02078cdbbac36950e`: cloned and inspected actual project/scenes. It contains a Downtown City MegaKit street layout, third-person controls and touch UI, but targets Godot 4.7 and explicitly selects Jolt. No repository-level licence for its project code was found; public source alone does not grant commercial reuse. The included Quaternius city kit's own `License_Standard.txt` says CC0, but that does not license the surrounding code. It was not run or adopted. Its separate kit assets can be evaluated from the original creator, with their licence checked independently.
- [Neonfire advanced third-person controller](https://github.com/NeonfireStudio/godot-advanced-third-person-controller) commit `6a168650e4c764c1465afdad3b20d1a7be8bc5ab`: its root MIT text conflicts with README statements restricting resale/tutorials and declaring model animations noncommercial. Its custom-character setup calls for many clips not currently available on approved Marcus. Do not import it without clarification of the relevant rights and a retargeting/visual test.
- [Godot 4 third-person shooter touchscreen fork](https://github.com/solodeveloping/godot4-third-person-shooter) commit `2ee520db2751e9d24fd1b511016a1384cd6e139b`: source project identifies Godot 4.4 and has touch-control scenes, and `CREDITS.md` lists MIT/CC0 and CC BY asset obligations. Actual checkout contains Git LFS pointers, including the preview and project icon; no complete playable launch was verified. It is a candidate for further source/asset licence and device evaluation, not a drop-in replacement.
- [GDQuest RoboBlast](https://www.gdquest.com/news/2022/12/godot-4-third-person-controller/) supplies a publicly playable demo and project, with MIT code and CC BY 4.0 art. Its cartoon robot/platform-shooter direction does not match the approved character or setting. Current source targets 4.7; no Xogot or local gameplay test was performed here.

**Selection:** none of these is approved or verified as a complete replacement for the owner's cinematic, warehouse and city. OpenCity's movement/vehicle behavior was physically exercised but its placeholder art is specifically unsuitable; the Godot TPS robot's geometry/animations loaded but its game was not tested. Selecting a source must not silently change story order, replace Marcus, or imply that target-device performance is solved.
